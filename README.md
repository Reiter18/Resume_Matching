# JobMatch — агрегатор вакансий с матчингом по ключевым словам

## Запуск

Всё сразу (Postgres, Redis, API, воркер, планировщик, фронтенд):

```bash
cp .env.example .env
docker compose up --build
```

- API: http://localhost:8000 (`/health`, `/sources`, документация `/docs`), фронтенд: http://localhost:5173
- Миграции применяются при старте `api` (`alembic upgrade head`). Новая миграция после изменения моделей: `cd backend && alembic revision --autogenerate -m "описание"`.

Локально без Docker для разработки:

```bash
docker compose up -d postgres redis
cd backend && pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
celery -A app.celery_app worker -Q ingest,default -l info
celery -A app.celery_app beat -l info
python -m app.cli seed-skills
python -m app.cli arbeitnow 1
python -m app.cli trudvsem 1
python -m app.cli dedup
python -m app.cli extract
python -m app.cli match
cd ../frontend && npm install && npm run dev
```

## Очереди и фоновые задачи (Celery + Redis)

- **Периодический сбор:** `beat` раз в `INGEST_INTERVAL_SECONDS` (по умолчанию 30 мин) ставит задачу `ingest_source` на каждый источник из `REGISTRY`. Новый источник подхватывается автоматически.
- **Очереди:** `ingest` для сбора, `default` для остального, в том числе матчинга (воркер слушает обе).
- **Цепочка:** сбор → `dedup_vacancies` → `match_new`. Пересчёт одного резюме (`match_resume`) ставится при загрузке резюме, правке ключевых слов и сохранении предпочтений.
- **Надёжность:** `acks_late` + `reject_on_worker_lost` — если воркер упал посреди задачи, она вернётся в очередь, а не потеряется.
- **Ретраи:** временные ошибки БД повторяются с нарастающей паузой (до 3 раз).
- **Мёртвая очередь:** задача, упавшая окончательно, сохраняется в таблицу `dead_letters` (имя, аргументы, ошибка) и не теряется.
- **Предохранитель источника:** после 5 сбоев подряд источник не опрашивается час (`BREAKER_*` в конфиге), чтобы не долбить упавший сайт. Остальные источники работают как обычно.
- **Наблюдаемость:** `GET /sources` показывает состояние каждого источника, `GET /health` — доступность БД и Redis.

## Деплой и мониторинг

Два окружения: `docker-compose.yml` для разработки (код монтируется, `--reload`, порты наружу) и `docker-compose.prod.yml` для сервера.

```bash
cp .env.prod.example .env
docker compose -f docker-compose.prod.yml up -d --build
```

- Наружу открыт только `web` (nginx, порт 80): отдаёт собранный фронтенд и проксирует `/api/` в API. БД, Redis и API снаружи недоступны. HTTPS ставится перед ним отдельно (Caddy, Traefik или certbot).
- `api` при старте применяет миграции и словарь навыков, `worker` и `beat` ждут, пока он станет healthy. Все сервисы с `restart: unless-stopped`, бэкенд работает не от root.
- За nginx API берёт реальный IP пользователя из `X-Forwarded-For`. Без этого ограничение попыток входа по IP считало бы всех одним клиентом.
- Обновление: `git pull && docker compose -f docker-compose.prod.yml up -d --build`.
- **Логи:** `docker compose -f docker-compose.prod.yml logs -f api worker`, уровень в `LOG_LEVEL` (по умолчанию INFO).
- **Мониторинг:** `GET /health` (БД и Redis, по нему же healthcheck контейнера `api`), `GET /sources` (состояние источников) и `GET /metrics` в формате Prometheus: `jobmatch_up{component}`, `jobmatch_vacancies_total`, `jobmatch_users_total`, `jobmatch_source_consecutive_failures{source}`, `jobmatch_source_last_success_age_seconds{source}`. Через nginx `/api/metrics` закрыт (404), Prometheus должен ходить в `api:8000/metrics` по внутренней сети. Что стоит алертить: `jobmatch_up == 0`, `jobmatch_source_last_success_age_seconds > 7200`, рост `jobmatch_source_consecutive_failures`.

## API

Документация и пробные запросы: http://localhost:8000/docs (кнопка Authorize, вставить токен из `/auth/login`).

| Метод и путь                            | Назначение                                                                                                                       |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/register`                   | регистрация (email без учёта регистра, пароль от 8 символов)                                                                     |
| `POST /auth/login`                      | вход, возвращает JWT (60 минут); после 5 неудачных попыток блокировка на 15 минут (429)                                          |
| `GET /me`, `PATCH /me`                  | текущий пользователь; смена имени                                                                                                |
| `POST /me/password`                     | смена пароля (нужен текущий)                                                                                                     |
| `DELETE /me`                            | удаление аккаунта с резюме и всеми данными (нужен пароль)                                                                        |
| `GET /vacancies`                        | список: `q`, `work_format`, `employment_type`, `min_salary`, `skill` (понимает синонимы), `limit` (до 50), `offset`              |
| `GET /vacancies/{id}`                   | вакансия с полным описанием и списком источников, где она опубликована (`also_found_at`)                                         |
| `POST /resumes`                         | загрузка резюме (PDF, DOCX или TXT, до 5 МБ), новое заменяет старое, ключевые слова и стаж находятся автоматически               |
| `POST /resumes/text`                    | резюме, вставленное текстом                                                                                                      |
| `GET /resumes/me/text`                  | полный извлечённый текст (проверить, что парсер понял резюме)                                                                    |
| `GET /resumes/me`, `DELETE /resumes/me` | своё резюме: просмотр и удаление                                                                                                 |
| `PUT /resumes/me/skills`                | ручная правка ключевых слов резюме (синонимы приводятся к словарю, повторы убираются)                                            |
| `GET /me/preferences`                   | предпочтения поиска: формат, занятость, график, места, часы, зарплата, обязательные критерии                                     |
| `PUT /me/preferences`                   | сохранить предпочтения (полная замена; ошибка 422, если обязательный критерий без значения)                                      |
| `GET /matches`                          | готовые оценки по убыванию: `min_score` (%), `limit`, `offset`; `pending: true`, пока оценки считаются; нужно резюме (иначе 404) |
| `GET /matches/{vacancy_id}`             | оценка одной вакансии с разбором по критериям, в том числе скрытой обязательными критериями (404, если оценки ещё нет)           |
| `GET /events`                           | поток SSE с обновлениями оценок текущего пользователя                                                                            |
| `POST /shares`                          | создаёт ссылку и возвращает токен один раз                                                                                       |
| `GET /shares`, `DELETE /shares/{id}`    | список своих ссылок и отзыв ссылки                                                                                               |
| `GET /skills?q=`                        | подсказки по словарю навыков для поля ввода                                                                                      |
| `POST /skills/normalize`                | приводит слова к каноническим именам: `Postgres` -> `postgresql`                                                                 |

Безопасность:

- Пароли хранятся как хеш argon2. На «неверный пароль» и «нет такого email» отвечаем одинаково и за одно время.
- Все эндпоинты, кроме регистрации и входа, требуют токен. Резюме привязано к пользователю: чужое получить нельзя, так как в API нет доступа по id.
- В не-dev окружении (`APP_ENV=prod`) приложение не стартует без своего `JWT_SECRET`. Сгенерировать: `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

Парсинг резюме (`app/resume_parser.py`): формат определяется по содержимому, а не по расширению.

- **PDF** (PyMuPDF): читаем строки, а не блоки; для резюме в две колонки порядок «левая колонка, потом правая» (ищем вертикальную просеку без строк); колонтитулы, повторяющиеся на страницах, убираются; строки вида «должность ... даты» колонками не считаются.
- **DOCX** (python-docx): абзацы и таблицы в порядке документа, объединённые ячейки не дублируются, защита от «zip-бомбы».
- **TXT**: UTF-8 или cp1251 (русские файлы из Блокнота).
- **Чистка текста:** лигатуры, неразрывные пробелы, маркеры списков, склейка переносов слов, номера страниц, управляющие символы.
- **Язык** резюме (ru / en / mixed) сохраняется: пригодится при подборе словаря навыков.
- Понятные ошибки: скан без текста, PDF с паролем, повреждённый файл, старый .doc, слишком длинный документ.
- Ограничения: сканы и картинки (OCR) не читаем; вложенные таблицы и текстовые рамки в DOCX пропускаются; определение колонок эвристическое. Навыки и опыт из текста извлекаются на следующих неделях.

## Словарь навыков

Таблицы `skills` и `skill_aliases`, данные в `app/skills_data.py` (140 навыков, около 290 синонимов на русском, английском и немецком). Загрузка: `python -m app.cli seed-skills` (безопасно запускать повторно, в docker compose выполняется при старте `api`).

- **Приведение к каноническому имени** (`app/skills.py`): `postgres`, `постгрес`, `PostgreSQL` -> `postgresql`; `Node JS`, `nodejs` -> `node.js`; `CI CD` -> `ci/cd`. Регистр, пробелы, дефисы и слэши не важны.
- **Вес навыка** (`skills.weight`) показывает, насколько он показателен: общие (git, sql, excel) 0.6, обычные 1.0, редкие (kubernetes, kafka, airflow) 1.4. Вес пойдёт в скоринг.
- **Категории:** language, framework, database, devops, cloud, tool, data, practice, mobile.
- **Сознательно не включены** двусмысленные короткие слова (go, c, r, next, cv): отличать их от обычных слов умеет только извлечение из текста (задача 5-й недели).
- Слова пользователя, которых нет в словаре, сохраняются, но помечаются (`unknown_skills`): с вакансиями они могут не совпасть.

## Извлечение навыков и параметров

Модуль `app/extract.py`, без ML: словарь навыков плюс регулярки.

- **Навыки:** ищутся слова и синонимы из словаря (с учётом падежей, `питона` даёт `python`), результат приводится к каноническому имени. Применяется к вакансиям при сборе и к резюме при загрузке.
- **Параметры вакансии:** формат работы, график, часы в неделю, минимальный опыт, зарплата (годовая переводится в месячную). Значения от источника важнее, пустые поля добираются из текста.
- **Стаж в резюме** берётся только если назван прямо («опыт 5 лет»), по датам не считается.
- **Ограничения:** отрицания не понимаются («kein Homeoffice» будет прочитано как гибрид); находятся только навыки из словаря.
- **Пересчёт** для уже сохранённых данных: `python -m app.cli extract`.

## Дедупликация вакансий

Одна вакансия приходит из разных источников или публикуется повторно. Дубль не удаляется, а получает `canonical_id` (ссылку на оригинал, то есть самую раннюю публикацию); в списке `GET /vacancies` показывается только оригинал.

1. **Кандидаты:** вакансии той же компании (`company_key`: без «GmbH», «ООО» и знаков, поэтому «Acme GmbH» и «ООО Acme» совпадают), опубликованные в окне +-90 дней.
2. **Город:** разные города значит разные вакансии, даже если текст одинаковый («Remote» и пустое значение совместимы с любым).
3. **Точный дубль:** совпал `content_hash`.
4. **Похожий дубль** (rapidfuzz): уровни junior/senior и цифры в названии должны совпадать; названия похожи не менее чем на 90%, и описания не менее чем на 75%; либо названия совпали (97%+) и описания не противоречат (55%+), иначе это разные команды с одинаковым названием позиции.
5. **Когда запускается:** задача Celery `dedup_vacancies` сразу после каждого сбора и команда `python -m app.cli dedup`. Проверяются только новые и изменившиеся вакансии (`dedup_checked_at`); если вакансию переписали, решение сбрасывается и принимается заново.

- Пороги проверены на размеченном наборе из 20 пар (`tests/test_dedup.py`), но он составлен вручную. После накопления реальных данных их стоит перепроверить.

## Защита входа от перебора

Счётчики неудачных попыток лежат в Redis и сами истекают: 5 попыток на пару (IP, email) и 30 на весь IP за 15 минут, затем ответ 429 с заголовком `Retry-After`. Успешный вход обнуляет счётчик пары. Если Redis недоступен, вход не блокируется (лучше пропустить проверку, чем закрыть сайт). Пороги в конфиге: `LOGIN_MAX_ATTEMPTS`, `LOGIN_IP_MAX_ATTEMPTS`, `LOGIN_WINDOW_SECONDS`. За обратным прокси нужно настроить передачу реального IP клиента, иначе все пользователи будут выглядеть как один адрес.

## Схема данных

sources — vacancies (source_id); users — search_preferences, share_links — vacancy_matches — resumes — users; skills — skill_aliases; notification_settings / notifications.

- **vacancies** хранит единый нормализованный формат. `UNIQUE(source_id, external_id)` даёт идемпотентный upsert.
- **skills / skill_aliases** — словарь ключевых слов и синонимов (postgres = postgresql). `skills.weight` — вес навыка в скоринге.
- **vacancies.skills** (массив, GIN-индекс) — ключевые слова вакансии; заполняет парсер.
- **Скор** — многокритериальный, 0..100%. Каждый критерий даёт оценку 0..1, итог = сумма (оценка x вес) / сумма весов применимых критериев.
  Если у вакансии нет данных (зарплата не указана) или у пользователя нет пожелания, критерий **не учитывается**, а веса пересчитываются.
  Критерии из `search_preferences.must_have` работают как жёсткий фильтр: при известном несовпадении вакансия скрывается (hybrid при желании «только remote» тоже несовпадение); если данных нет, вакансия остаётся.

  | Критерий                                                      | Вес | Оценка                                                                              |
  | ------------------------------------------------------------- | --- | ----------------------------------------------------------------------------------- |
  | Навыки (ключевые слова)                                       | 40  | сумма весов совпавших / сумма весов навыков вакансии                                |
  | Формат работы (remote / hybrid / onsite)                      | 15  | совпало = 1, hybrid рядом с remote или onsite = 0.5, иначе 0                        |
  | Зарплата (в месяц, одна валюта)                               | 15  | верхняя граница >= желаемой = 1, иначе пропорционально; не указана = не учитывается |
  | Локация                                                       | 10  | город совпал = 1; для remote-вакансии не нужна                                      |
  | Тип занятости (full_time / part_time / contract / internship) | 10  | входит в список желаемых = 1                                                        |
  | График                                                        | 2.5 | график входит в желаемые = 1                                                        |
  | Часы в неделю                                                 | 2.5 | часы в желаемом диапазоне = 1                                                       |
  | Опыт (лет)                                                    | 5   | опыт резюме >= требуемого = 1, иначе пропорционально                                |

  Веса — константы в коде, их можно подобрать на ресерче.

- **search_preferences** — пожелания пользователя (формат, занятость, график, часы, зарплата, локации) и список обязательных критериев.
- **vacancy_matches.explanation (JSONB)** — «почему 85%»: по каждому критерию score, weight, status (match / partial / mismatch / unknown) и пояснение; для навыков ещё списки matched и missing.
- **content_hash + dedup_key + canonical_id** — основа дедупликации: дубль указывает на оригинал.
- **sources.consecutive_failures / last_error** — состояние источника для отказоустойчивости.

## Скоринг v1

Код: `app/scoring.py` (чистая функция `score_vacancy`, без БД), пайплайн `app/matching.py`, эндпоинты `/matches`.

- В API скор в процентах (0..100), `null`, если сравнивать не с чем. У каждого критерия: `score` (0..1 или `null`), `weight`, `status`, `text` с пояснением; для навыков ещё `matched` и `missing`.
- `summary.matches`, `summary.gaps` и `summary.unknown` объясняют, что совпало, чего не хватает и каких данных нет. У критерия `applicable: false` означает, что он неприменим к профилю пользователя. Для сохранённых ранее оценок выполните `docker compose exec api python -m app.cli match`.
- Валюты не конвертируются: если валюта вакансии не совпала с желаемой, зарплата не учитывается.
- Совпадение места: желаемый город входит в место вакансии без учёта регистра («Berlin» найдёт «Berlin, Germany»).

## Пайплайн матчинга

Оценки считаются заранее и хранятся в `vacancy_matches` (по одной строке на пару «резюме + вакансия»), поэтому `GET /matches` это обычный SQL с сортировкой и пагинацией.

- **Новые вакансии:** после сбора и дедупликации задача `match_new` оценивает для каждого резюме вакансии без оценки и те, что обновились после неё (`created_at` оценки старше `fetched_at` вакансии). Дубли не оцениваются. Считаются 5000 самых свежих вакансий.
- **Смена резюме, навыков или предпочтений:** задача `match_resume` пересчитывает все оценки этого резюме. Обязательные критерии применяются здесь же: неподходящие вакансии получают `hidden = true` и из ленты пропадают, но их оценка остаётся доступной по прямой ссылке.
- **Идемпотентность:** запись через `INSERT ... ON CONFLICT DO UPDATE`, повторный или параллельный запуск безопасен.
- **Если очередь недоступна:** запрос пользователя не падает, а `match_new` по расписанию (каждые `INGEST_INTERVAL_SECONDS`) догонит пропущенное. Пока оценок нет совсем, `GET /matches` отдаёт `pending: true`.
- **После изменения весов или правил скоринга:** `python -m app.cli match` пересчитывает всё.

### Обновления в реальном времени

После сохранения оценок воркер публикует в Redis `matches_refreshed` или `new_matches`. Браузер слушает `GET /events` с токеном в заголовке Authorization и обновляет ленту и разбор оценки. В продакшене nginx проксирует `/api/events` без буферизации.

## Ресерч весов скоринга

`backend/research/evaluate.py` сравнивает «только навыки» и многокритериальный скоринг и перебирает долю навыков в итоге на размеченной выборке: профиль (резюме и пожелания) и вакансии с меткой `label` 1/0, которую ставит человек. Метрики: AUC (вероятность, что подходящая вакансия стоит выше неподходящей) и P@3 (доля подходящих в первой тройке). Вакансии, скрытые обязательными критериями, считаются стоящими в конце списка.

```bash
python -m research.evaluate
python -m research.evaluate export USER_ID 30 > research/mine.json
python -m research.evaluate research/mine.json
```

## Публичные ссылки

Сценарий: соискатель делится подборкой вакансий с ментором или карьерным центром, не открывая резюме и аккаунт.

- Токен случайный (256 бит), в БД лежит только его **хеш** (`share_links.token_hash`); токен виден один раз при создании.
- **Белый список полей** (`sharing.ALLOWED_FIELDS`): вакансии и оценки, разбор по критериям, навыки, зарплатные ожидания. Резюме, email и контакты открыть нельзя. Лишние поля в запросе отклоняются.
- При создании можно задать заголовок, поля для показа, минимальный скор (0–100%) и срок (1–365 дней, по умолчанию 7). У пользователя может быть до 20 активных ссылок. Повторный отзыв сохраняет дату первого.

## Нормализация критериев

Все источники приводятся к одному словарю значений: `work_format` (remote / hybrid / onsite / unknown), `employment_types`, `schedule`, `hours_per_week`, зарплата в месяц.
Arbeitnow даёт только remote/не remote, поэтому hybrid определяется по словам в тексте, а график и часы обычно остаются пустыми (unknown).
«Работа России» также передаёт график, зарплату в рублях, требуемый опыт и часть навыков.

## Коннекторы

`BaseConnector.fetch()` отдаёт `NormalizedVacancy`. Новый источник = один класс + строка в `REGISTRY`.
Ретраи с экспоненциальной паузой на 5xx/429/таймауты, `SourceUnavailable` вместо падения,
битая запись пропускается, сбой источника пишется в `sources`.

- **Arbeitnow** (`arbeitnow`) — европейские вакансии.
- **«Работа России»** (`trudvsem`) — [открытый API вакансий](https://opendata.trudvsem.ru/api/v1/vacancies?limit=1) без ключа. Коннектор ищет по запросам «python», «программист» и «разработчик». Число после имени источника задаёт максимум страниц на каждый запрос.

Ручной сбор и пересчёт из корня проекта:

```bash
docker compose exec api python -m app.cli trudvsem 1
docker compose exec api python -m app.cli dedup
docker compose exec api python -m app.cli match
```
