# JobMatch — агрегатор вакансий с матчингом по ключевым словам

## Запуск

Всё сразу (Postgres, Redis, API, воркер, планировщик, фронтенд):

```bash
cp .env.example .env
docker compose up --build
```

- API: http://localhost:8000 (`/health`, `/sources`, документация `/docs`), фронтенд: http://localhost:5173
- Миграции применяются при старте `api` (`alembic upgrade head`). Новая миграция после изменения моделей: `cd backend && alembic revision --autogenerate -m "описание"`.

Локально без Docker для разработки:

```bash
docker compose up -d postgres redis
cd backend && pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
celery -A app.celery_app worker -Q ingest,default -l info
celery -A app.celery_app beat -l info
python -m app.cli arbeitnow 1
cd ../frontend && npm install && npm run dev
```

## Очереди и фоновые задачи (Celery + Redis)

- **Периодический сбор:** `beat` раз в `INGEST_INTERVAL_SECONDS` (по умолчанию 30 мин) ставит задачу `ingest_source` на каждый источник из `REGISTRY`. Новый источник подхватывается автоматически.
- **Отдельные очереди:** `ingest` для сбора; матчинг получит свою, чтобы не мешать сбору.
- **Надёжность:** `acks_late` + `reject_on_worker_lost` — если воркер упал посреди задачи, она вернётся в очередь, а не потеряется.
- **Ретраи:** временные ошибки БД повторяются с нарастающей паузой (до 3 раз).
- **Мёртвая очередь:** задача, упавшая окончательно, сохраняется в таблицу `dead_letters` (имя, аргументы, ошибка) и не теряется.
- **Предохранитель источника:** после 5 сбоев подряд источник не опрашивается час (`BREAKER_*` в конфиге), чтобы не долбить упавший сайт. Остальные источники работают как обычно.
- **Наблюдаемость:** `GET /sources` показывает состояние каждого источника, `GET /health` — доступность БД и Redis.

## API

Документация и пробные запросы: http://localhost:8000/docs (кнопка Authorize, вставить токен из `/auth/login`).

| Метод и путь                            | Назначение                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------------- |
| `POST /auth/register`                   | регистрация (email без учёта регистра, пароль от 8 символов)                           |
| `POST /auth/login`                      | вход, возвращает JWT (живёт 60 минут)                                                  |
| `GET /me`, `PATCH /me`                  | текущий пользователь; смена имени                                                      |
| `POST /me/password`                     | смена пароля (нужен текущий)                                                           |
| `DELETE /me`                            | удаление аккаунта с резюме и всеми данными (нужен пароль)                              |
| `GET /vacancies`                        | список: `q`, `work_format`, `employment_type`, `min_salary`, `limit` (до 50), `offset` |
| `GET /vacancies/{id}`                   | вакансия с полным описанием                                                            |
| `POST /resumes`                         | загрузка резюме (PDF, DOCX или TXT, до 5 МБ), новое заменяет старое                    |
| `POST /resumes/text`                    | резюме, вставленное текстом                                                            |
| `GET /resumes/me/text`                  | полный извлечённый текст (проверить, что парсер понял резюме)                          |
| `GET /resumes/me`, `DELETE /resumes/me` | своё резюме: просмотр и удаление                                                       |

Безопасность:

- Пароли хранятся как хеш argon2. На «неверный пароль» и «нет такого email» отвечаем одинаково и за одно время.
- Все эндпоинты, кроме регистрации и входа, требуют токен. Резюме привязано к пользователю: чужое получить нельзя, так как в API нет доступа по id.
- В не-dev окружении (`APP_ENV=prod`) приложение не стартует без своего `JWT_SECRET`. Сгенерировать: `python -c "import secrets; print(secrets.token_urlsafe(48))"`.

Парсинг резюме (`app/resume_parser.py`): формат определяется по содержимому, а не по расширению.

- **PDF** (PyMuPDF): читаем строки, а не блоки; для резюме в две колонки порядок «левая колонка, потом правая» (ищем вертикальную просеку без строк); колонтитулы, повторяющиеся на страницах, убираются; строки вида «должность ... даты» колонками не считаются.
- **DOCX** (python-docx): абзацы и таблицы в порядке документа, объединённые ячейки не дублируются, защита от «zip-бомбы».
- **TXT**: UTF-8 или cp1251 (русские файлы из Блокнота).
- **Чистка текста:** лигатуры, неразрывные пробелы, маркеры списков, склейка переносов слов, номера страниц, управляющие символы.
- **Язык** резюме (ru / en / mixed) сохраняется: пригодится при подборе словаря навыков.
- Понятные ошибки: скан без текста, PDF с паролем, повреждённый файл, старый .doc, слишком длинный документ.
- Ограничения: сканы и картинки (OCR) не читаем; вложенные таблицы и текстовые рамки в DOCX пропускаются; определение колонок эвристическое. Навыки и опыт из текста извлекаются на следующих неделях.

## Схема данных

sources — vacancies (source_id); users — search_preferences, share_links — vacancy_matches — resumes — users; skills — skill_aliases; notification_settings / notifications.

- **vacancies** хранит единый нормализованный формат. `UNIQUE(source_id, external_id)` даёт идемпотентный upsert.
- **skills / skill_aliases** — словарь ключевых слов и синонимов (postgres = postgresql). `skills.weight` — вес навыка в скоринге.
- **vacancies.skills** (массив, GIN-индекс) — ключевые слова вакансии; заполняет парсер.
- **Скор** — многокритериальный, 0..100%. Каждый критерий даёт оценку 0..1, итог = сумма (оценка x вес) / сумма весов применимых критериев.
  Если у вакансии нет данных (зарплата не указана) или у пользователя нет пожелания, критерий **не учитывается**, а веса пересчитываются.
  Критерии из `search_preferences.must_have` работают как жёсткий фильтр: при известном несовпадении вакансия скрывается.

  | Критерий                                                      | Вес | Оценка                                                                              |
  | ------------------------------------------------------------- | --- | ----------------------------------------------------------------------------------- |
  | Навыки (ключевые слова)                                       | 40  | сумма весов совпавших / сумма весов навыков вакансии                                |
  | Формат работы (remote / hybrid / onsite)                      | 15  | совпало = 1, hybrid рядом с remote или onsite = 0.5, иначе 0                        |
  | Зарплата (в месяц, одна валюта)                               | 15  | верхняя граница >= желаемой = 1, иначе пропорционально; не указана = не учитывается |
  | Локация                                                       | 10  | город совпал = 1; для remote-вакансии не нужна                                      |
  | Тип занятости (full_time / part_time / contract / internship) | 10  | входит в список желаемых = 1                                                        |
  | График и часы в неделю                                        | 5   | график совпал и часы в диапазоне                                                    |
  | Опыт (лет)                                                    | 5   | опыт резюме >= требуемого = 1, иначе пропорционально                                |

  Веса — константы в коде, их можно подобрать на ресерче.

- **search_preferences** — пожелания пользователя (формат, занятость, график, часы, зарплата, локации) и список обязательных критериев.
- **vacancy_matches.explanation (JSONB)** — «почему 85%»: по каждому критерию score, weight, status (match / partial / mismatch / unknown) и пояснение; для навыков ещё списки matched и missing.
- **content_hash + dedup_key + canonical_id** — основа дедупликации: дубль указывает на оригинал.
- **sources.consecutive_failures / last_error** — состояние источника для отказоустойчивости.

## Публичные ссылки

Сценарий: соискатель делится подборкой вакансий с ментором или карьерным центром, не открывая резюме и аккаунт.

- Ссылка `/s/<токен>` работает без регистрации, только на чтение, подборка живая (обновляется при новых вакансиях).
- Токен случайный (256 бит), в БД лежит только его **хеш** (`share_links.token_hash`); токен виден один раз при создании.
- **Белый список полей** (`sharing.ALLOWED_FIELDS`): вакансии и оценки, разбор по критериям, навыки, зарплатные ожидания. Резюме, email и контакты открыть нельзя. Лишние поля в запросе отклоняются.
- Параметры ссылки: что показывать, минимальный скор, срок действия, отзыв, счётчик просмотров.
- Защита публичного эндпоинта: лимит запросов (Redis), `noindex`, одинаковый ответ на «нет такой ссылки» и «ссылка отозвана».

## Нормализация критериев

Все источники приводятся к одному словарю значений: `work_format` (remote / hybrid / onsite / unknown), `employment_types`, `schedule`, `hours_per_week`, зарплата в месяц.
Arbeitnow даёт только remote/не remote, поэтому hybrid определяется по словам в тексте, а график и часы обычно остаются пустыми (unknown).
Богаче данные у Trudvsem (график, зарплата) — это одна из причин взять его вторым источником.

## Коннекторы

`BaseConnector.fetch()` отдаёт `NormalizedVacancy`. Новый источник = один класс + строка в `REGISTRY`.
Ретраи с экспоненциальной паузой на 5xx/429/таймауты, `SourceUnavailable` вместо падения,
битая запись пропускается, сбой источника пишется в `sources`.
